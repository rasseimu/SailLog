# スキャンPDF → エージェントが読めるテキスト化 手順

画像だけのスキャンPDF（文字認識されていないPDF）を、正しい読み順・校正済みのプレーンテキストにするための手順。
2026-09 に『Winning in 470』(見開きスキャン, 日本語横書き2段組) で確立。

---

## 0. まず判定：本当にOCRが必要か

```bash
pdfinfo "対象.pdf" | grep -E "Pages|Page size"
pdftotext "対象.pdf" - | wc -c
```

- 抽出文字数が「ページ数と同じ程度（＝改ページ記号だけ）」なら画像のみ＝OCR必要。
- 既に数千字/ページ抽出できるならテキスト層あり。`pdftotext 対象.pdf out.txt` で終わり。

---

## 手順A：とりあえずテキスト層付きPDFがほしい（軽量・機械処理向け）

見た目そのままにテキストレイヤーを埋め込む。**レイアウトが単純（1段組）なら十分。**

```bash
brew install ocrmypdf tesseract-lang pngquant jbig2enc   # 初回のみ
ocrmypdf -l jpn+eng --pdf-renderer sandwich --output-type pdf \
  --rotate-pages --optimize 3 --force-ocr "元.pdf" "元_OCR.pdf"
pdftotext "元_OCR.pdf" - | wc -c   # 数万字出れば成功
```

### 必須の注意（このMacの落とし穴）
- **`--pdf-renderer sandwich` は必須。** 既定(hocr)レンダラは Homebrew python@3.14 の壊れた `pyexpat`
  （`Symbol not found: _XML_SetAllocTrackerActivationThreshold`）でクラッシュする。
  → 詳細は memory の `ocrmypdf-py314-expat-fix`。yt-dlpのpy3.14問題と同根。
- **`--output-type pdf`**（既定のpdfaはGhostscriptのPDF/A化で "invalid jpeg / PDF is INVALID" 警告が出る）。
- **サイズが100MB超に膨らむと Claude の Read (PDF) 上限に引っかかる。**
  - `--deskew` は再エンコードで肥大化するので、上限に当たるなら外す。
  - `--optimize 3`（pngquant + jbig2enc 必要）で大幅圧縮できる（例: 76MB→59MB）。
- 日本語OCRは字間にスペースが入る癖あり（意味は読める。機械処理時は要スペース除去）。

---

## 手順B：読める整形テキストがほしい（段組み・見開き・校正が必要なとき）★推奨

OCR生テキストは **2段組みが1列に混線／文字抜け** が起きる。
精度が要るなら OCRテキストを直すより **ページ画像から起こし直す** 方が速くて正確。

### B-1. サブエージェントが読める場所にPDFを置く
Claudeのサブエージェントは**作業ディレクトリ外（例 `~/Downloads`）のReadを自動拒否**する。
→ プロジェクト内にコピーする（設定を自分で書き換えて回避しようとすると「Auto-Mode Bypass」で弾かれる）。

```bash
mkdir -p <project>/_src && cp "~/Downloads/元.pdf" "<project>/_src/元.pdf"
```

### B-2. ページ単位で並列サブエージェントに転写させる
- PDF 1ページ ≒ 見開き2ページのことが多い。まず自分で1枚 Read して**レイアウト（段組み・縦横・ページ番号位置）を確認**。
- 1エージェント＝3〜4 PDFページ担当で並列ディスパッチ（独立作業なので並列が最適）。
- **プロンプトに必ず入れる指示：**
  - 対象PDFの絶対パスと担当ページ（`Read` の `pages` 引数で1枚ずつ）
  - 見開きは **左ページ→右ページ**、段組みは **左列を最後まで→右列**（最頻出のOCR誤り）
  - 画像から直接転写（埋め込みテキスト層に頼らない）／逐語・要約翻訳しない
  - 字間の余分なスペース除去／判読不能は `[?]` か `〓`
  - 見出し・本文・`写真N`/`図N`ラベルとキャプション・柱（ヘッダー）も全部拾う
  - 出力は `===== p.NN =====` 区切りの生テキストのみ（前置き・注記なし）

### B-3. 結果の回収（通知が来なくても大丈夫）
`/login` 等で割り込むと完了通知が届かないことがある。その場合は各エージェントの
トランスクリプト最終行から本文だけ抽出（画像base64を避ける）：

```
~/.claude/projects/<proj-slug>/<session>/subagents/agent-<id>.jsonl
```

python で全行を走査し、最後の role=="assistant" の text ブロックだけを取り出して `.txt` 保存。
（`.output` スタブは145バイトの起動通知のみで進捗判定には使えない。`.jsonl` の mtime/サイズで作業有無を見る）

### B-4. 連結・校正して出力
python で順番に連結しつつ機械的にクリーニング：
- 先頭の前置き行（最初の `=====` まで）を捨てる
- 末尾のエージェント注記（`---` / `Transcription complete` / `Done.` / `Note:` …）以降を捨てる
- 列位置マーカー `■（左ページ…）` や手書きメモ行 `（手書き…）` を除去（残したいなら残す）
- スキャン由来の誤字を置換（例 `cong`→`である`、`さCDて`→`さて`）
- 空行3連続→1つに圧縮
- 章ごとに見開き境界の**段落重複**が出ることがある（隣接ページを二重読み）。
  完全版を残し、途中で切れた重複版を消す。

### B-5. 検証
- `grep -c "^====="` でページ数、`wc -m` で文字数を確認
- 重複段落を `grep -c "特徴的な一文"` で 1 になるか確認
- 自分で数ページ Read して読み順・意味が通るか目視

---

## 出力の目安（実績）
- 入力: 76MB / 35ページ, 抽出35字（＝画像のみ）
- 出力: 校正済みテキスト 約69,000字、読み順復元・重複解消済み

## 後片付け
中間物（コピーPDF、`_parts/*.txt`、OCR版PDF、`/tmp` テスト）は最終txtができたら削除してよい。
**元のPDFは消さない。**
